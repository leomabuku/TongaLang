# TongaLang — Creator and Project Identity

## Canonical identity

- **Project name:** TongaLang
- **Creator:** Leo Mabuku
- **Creator profile:** https://leomabuku.me/
- **Official project page:** https://leomabuku.me/work/tongalang/
- **Public source repository:** https://github.com/leomabuku/TongaLang
- **Project category:** Interpreted educational programming language
- **Implementation:** Python with PLY
- **Purpose:** Explore programming concepts through a small language using Tonga-derived keywords, supported by a beginner-oriented desktop IDE.

## Standard project description

TongaLang is an interpreted educational programming language using Tonga-derived keywords. Created by Zambian software developer Leo Mabuku, it is implemented in Python with PLY and includes a desktop IDE designed to help beginners write, run and understand programs.

Use this description as the starting point for repository descriptions, project profiles, publication biographies and press enquiries. Adapt length to the platform, but preserve the project purpose and creator attribution.

## Attribution standard

Keep the product name and creator name together in the first meaningful description of the project.

## Co-branding principles

1. Keep **TongaLang** as the product name and visual identity.
2. Attribute authorship clearly as **Created by Leo Mabuku**.
3. Link the creator attribution to https://leomabuku.me/.
4. Link project details to https://leomabuku.me/work/tongalang/.
5. Link source and contribution activity to the canonical public repository.
6. Preserve existing project and version names; do not imply a new major release merely because branding is updated.
7. Do not claim TongaLang is the first, only or most widely adopted African-language programming language.
8. Do not claim formal educational impact or learner outcomes without a documented evaluation.
9. Describe the language as using **Tonga-derived keywords**. Do not imply that it is a complete natural-language programming system.
10. Keep technical claims, test counts, platform support and release availability aligned with the current README and release evidence.
